# QQ 空间 UIN 身份与模块化重构

> 适用提交：QQ 空间 UIN 身份防护与模块化重构
> 更新日期：2026-08-04
> 面向读者：插件使用者、维护者、代码审阅者

## 1. 更新目标

本次更新同时解决两个问题：

1. QQ 空间查看结果中，Bot 曾可能只依据昵称或未明确的查看对象进行叙述，进而把用户或第三方的说说误认为 Bot 自己的经历。
2. 原 `qzone_integration.py` 集中了运行时连接、Cookie、动态解析、评论、发布、计划、认证和媒体上传等职责，文件过大，维护时很难判断一项改动会影响哪些路径。

更新后的目标是：**以 QQ UIN 作为唯一身份事实，归属不清时停止而不是猜测；同时保持 QQ 空间能力的公开入口兼容，并把实现按职责拆开。**

## 2. 用户可感知的行为变化

### 2.1 查看说说必须先确定对象

`pc_qzone_view_feed` 不再在目标缺失时默认把命令发送者当作查看对象。调用方需要明确给出以下之一：

| 用户意图 | 工具参数 | 目标 UIN 来源 |
| --- | --- | --- |
| “看我自己的说说” | `target_scope="current_user"` | 当前消息发送者的 QQ UIN |
| “看你自己的说说” | `target_scope="bot_self"` | OneBot 登录账号的 QQ UIN |
| “看 123456 的说说” | `target_scope="explicit_uin"` 与 `target_uin="123456"` | 明确指定的 QQ UIN |
| 旧调用兼容 | 明确的 `user_id="123456"` | 仅作为显式 UIN，不再充当默认值 |

“她/他/TA/自己的”等指代必须有清晰前指；没有可确认对象时，工具返回 `needs_target` 并要求确认，而不会按昵称、性别或人设猜测。

### 2.2 返回作者必须和目标 UIN 一致

QQ 空间响应中的 `author.uin` / 动态作者 UIN 是唯一可信身份。工具会在读取后再次比对：

```text
明确请求目标 UIN
    -> 查询 QQ 空间
    -> 返回作者 UIN
    -> 必须等于请求目标 UIN
    -> 才允许输出正文、点赞或评论
```

结果会带上 `identity` 字段：

| 字段 | 含义 |
| --- | --- |
| `requested_scope` | 本次请求是 Bot、自身用户还是显式 QQ 号 |
| `target_uin` | 已确认的查询目标 |
| `owner_uin` | QQ 空间响应中返回的作者 UIN |
| `owner_role` | `bot_self`、`current_user`、`third_party` 或失败/歧义状态 |
| `owner_matches_target` | 返回作者是否与请求目标一致 |
| `pronoun_safe` | 是否允许按归属使用人称 |
| `memory_policy` | 是否可以进入长期记忆 |

以下情况会安全停止，不返回可能误导模型的正文：

- 返回作者 UIN 缺失：`identity_unverified`；
- 返回作者 UIN 与请求目标不同：`identity_mismatch`；
- Bot 与当前用户恰好使用同一 UIN：`identity_ambiguous`；
- `selector` 里夹带的 QQ 号试图覆盖已经确认的目标：`invalid_target`。

### 2.3 人称与长期记忆边界

UIN 比对成功后，工具会给模型提供明确的归属约束：

- `bot_self`：可以按 Bot 自己的空间动态表述；
- `current_user`：只能表述为当前用户的动态，不能称为 Bot 的经历；
- `third_party`：不能称为 Bot 或当前用户的经历；
- 歧义或不一致：不使用“我/你/她”等归属性人称。

任何成功查看 QQ 空间后的被动回复都会跳过 LivingMemory 和 MemoryCompanion 的长期写入，仍保留当前会话的已送达回复记录。这样“查看到的公开内容”不会被沉淀为 Bot 的自传、经历或关系事实。

## 3. 改动理由

QQ 空间返回的昵称可以重复、变化，也可能与 Bot 人设名称相同；它不能作为身份依据。此前如果“查看对象”为空，旧行为会把当前用户作为默认目标，随后模型看到作者昵称和说说正文，可能出现如下错误链：

```text
用户要求查看自己的说说
    -> 查询成功
    -> 未对作者 UIN 与目标 UIN 做闭环校验
    -> 模型把内容带入 Bot 视角
    -> 最终回复进入长期记忆
```

本次改动把身份确认提前到网络请求之前，并在网络响应之后重复验证。归属缺失或冲突时宁可要求确认，也不继续生成容易污染上下文、记忆或关系判断的描述。

## 4. 模块结构

原 `qzone_integration.py` 为 4485 行单体实现。现在它保留为 52 行兼容门面，原有 `QzoneMixin` 入口不变，具体职责拆分如下：

```text
QzoneMixin（稳定兼容门面）
├── QzoneCommentMixin     评论身份、回复决策、评论收件箱
├── QzoneScheduleMixin    发布时间窗、每日计划、自动发布生命周期
├── QzonePublishMixin     文案生成、清理、发布记录、配图准备
├── QzoneFeedMixin        动态/评论解析、查询、点赞、删除、直接评论
├── QzoneRuntimeMixin     OneBot 运行时发现、Cookie、HTTP 传输
└── QzoneMediaMixin       图片读取、校验、上传、发布请求
    └── QzoneAuthMixin    登录失败状态、H5 token、平台动作调用

QzoneIntegrationError     独立的共享异常类型
```

### 4.1 文件职责和改动理由

| 文件 | 责任 | 这样拆分的原因 |
| --- | --- | --- |
| `qzone_integration.py` | 稳定门面、旧常量和旧补丁入口 | 外部调用继续只依赖 `QzoneMixin`，内部可以独立演进 |
| `qzone_runtime.py` | OneBot 连接发现、Cookie 读取、HTTP 请求 | 连接与传输失败不应和动态解析、发布逻辑混在一起 |
| `qzone_feed.py` | 动态解析、读取、点赞、删除、直接评论 | 响应数据兼容和内容操作可单独测试 |
| `qzone_comments.py` | 评论作者识别、回复策略、收件箱 | 评论幂等和回复决策与公开发布生命周期分离 |
| `qzone_publish.py` | 说说文案、清理、历史、配图准备 | 文案质量与媒体网络请求可以分别维护 |
| `qzone_schedule.py` | 每日计划、窗口、重试和自动生命周期 | 时间调度规则集中，避免和即时工具路径耦合 |
| `qzone_auth.py` | 认证失败状态、H5 qzonetoken、平台动作 | 登录态/授权失败形成明确边界，媒体层不再承担认证职责 |
| `qzone_media.py` | 图片安全校验、下载、上传、发布请求 | 网络媒体处理集中，并通过继承复用认证能力 |
| `qzone_errors.py` | `QzoneIntegrationError` | 防止错误类型依赖媒体模块，降低导入耦合 |
| `qzone_selection.py` | UIN 归一化、请求目标解析、返回作者分类 | 身份判断成为独立、可直接测试的纯逻辑 |

每个新模块都有模块说明、`__all__` 和聚焦的 Mixin 名称。新增结构契约测试固定门面组合顺序与关键方法归属，避免未来把新职责重新塞回单体文件。

## 5. 兼容性承诺

- 业务代码和第三方扩展仍从 `qzone_integration.QzoneMixin` 使用 QQ 空间能力。
- 旧的 `qzone_media.QzoneIntegrationError` 导入继续有效；门面也继续导出相同异常类型。
- 旧的 `user_id` 仅在它是明确合法 QQ UIN 时保留兼容；空值不再默认为当前用户。
- 自动发布测试或扩展对 `qzone_integration.random.random` 的补丁继续有效。
- 不改变 QQ 官方平台不能使用 QQ 空间、OneBot 可使用 QQ 空间的既有平台边界。

## 6. 预期效果

### 对使用者

- “看我的说说”和“看 Bot 的说说”不再因同名昵称、默认目标或模型推断被混淆。
- 动态结果会携带可审计的 UIN 归属，问题排查时能直接看到请求对象与返回作者是否一致。
- 身份不完整时得到明确的确认提示，不会收到看似自然但归属错误的回答。
- 查看用户或第三方公开内容不会反向写成 Bot 的长期经历。

### 对维护者

- 维护者可以按功能定位文件，不必在单个数千行文件中查找认证、解析、调度或上传逻辑。
- 模块之间通过 `QzoneMixin` 保持稳定的调用面，重构风险集中在内部。
- 认证、媒体、调度、评论和动态解析可以各自增加回归测试，减少跨功能误伤。

## 8. 审阅关注点

审阅本次更新时，建议优先检查：

1. `QzoneViewTarget` 是否在请求前完成目标解析，并且没有空目标默认回退；
2. 返回动态的 `author.uin` 是否必须与 `target_uin` 一致；
3. `identity` 失败分支是否在输出正文、点赞、评论之前返回；
4. QQ 空间查看回复是否被长期记忆写入保护拦截；
5. `QzoneMixin`、异常类型和自动发布补丁路径是否仍兼容；
6. 新增的模块边界测试是否能阻止职责回流。

## 9. 后续维护规则

- 新的 QQ 空间能力先判断归属属于运行时、动态、评论、发布、调度、认证还是媒体，再放入对应模块；不要再向门面文件堆放实现。
- 一切“是谁的空间内容”判断只能使用规范化 UIN，昵称、头像、性别和人设不构成身份凭据。
- 若新增查看结果字段或新的记忆通道，必须同时检查其是否会把公开动态写入 Bot 的长期经历。
- 新增关键职责时，补充 `tests/test_qzone_module_boundaries.py` 或相应行为回归测试。
